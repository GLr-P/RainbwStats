# Meta research: how the site tiers and meta data are built

The recommender's map/site knowledge comes from `src/shared/data/meta.json`, generated by
`scripts/research/build-meta.ts` from three kinds of evidence. Rerun this every patch / new season.
There is no single perfect source, so each one covers a different blind spot:

| Source | What it gives | How it is collected | Blind spot |
|---|---|---|---|
| **siegestrats.com** strat pages | Per **site** defender and attacker lineups from creators, pro write-ups and team drawings (≈340 strats) | `scripts/research/siegestrats.mjs` reads each strat page's structured data (map, side, site, operators, dates, cited sources) | Community curation; some lineups cite older videos |
| **Liquipedia** pro matches | Pro **operator bans per map** for the latest pro stages and Major | `scripts/research/liquipedia.mjs` parses match popups via the official API (1 parse / 30 s) | Bans only (not picks), pro coordination ≠ ranked |
| **Ubisoft Designer's Notes** (mid-season) | Official **ranked** PC Platinum+ ban rates and win delta vs presence per operator (win delta is aggregated per bomb site) | Read the charts manually into `research/manual/ranked.json` (charts are images; only confidently identified operators) | No per-site breakdown; icons on scatter plots must be identified by hand |

## Procedure (each new patch / season)

1. **Check what changed.** Read Ubisoft's patch notes + Designer's Notes for the patch (news-updates on ubisoft.com).
   Note new operators, reworks, map reworks / site moves (e.g. Y11S3 moved Villa's Living Room/Library site to the basement)
   and the **ranked map pool**. Update `research/manual/patch.json` (season, patch, pool, notable changes).
2. **Ranked data.** From the latest Designer's Notes, copy PC Platinum+ **ban rates** (bar charts are labelled) and the
   **win delta** of operators you can identify with certainty (use the labelled ban charts to learn icons) into
   `research/manual/ranked.json`. Leave out anything uncertain.
3. **Pro data.** Update `DEFAULT_PAGES` in `scripts/research/liquipedia.mjs` to the latest league stages / Major, then run
   `node scripts/research/liquipedia.mjs` (≈6 min because of Liquipedia's rate limit; pages are cached).
4. **Site lineups.** Run `node scripts/research/siegestrats.mjs --refresh` (≈5 min, polite, cached).
5. **Build.** `npx tsx scripts/research/build-meta.ts` → writes `src/shared/data/meta.json` (bundled), then
   `npm run export-dataset` → `site/data/meta/latest.json` (downloaded by the app, so data updates don't need an app release).
   Expert corrections go in `research/manual/overrides.json` (recorded as overrides, never as research).
   It prints a coverage report: sites with too little evidence fall back to the curated tiers in `sitePicks.ts`
   (site names are matched by room names, so small naming differences are tolerated).
6. **Sanity check** with real data: `npx tsx` the variety/audit scripts (see PLAN.md log) on a copy of a real profile,
   then `npm run check`. Spot-check a few sites you know well.
7. Bump the dataset `version`, commit, push (Pages serves the new JSON), release if code changed.

## How evidence becomes tiers (build-meta.ts)

- Per site and side: each strat lineup is one vote per operator, weighted by recency (strat modified in the last
  6 months = 1, older = 0.5). Share = votes / total lineups.
  **S** = ≥ 3 lineups agree and share ≥ 45 %, **A** = ≥ 2 lineups agree and share ≥ 20 %. Fewer than 2 lineups on a side →
  curated tiers. The recommender scales site value by evidence (5+ lineups = full, 2 ≈ 70 %, curated = 70 %).
- Per map: operators banned in ≥ 25 % of pro games on that map are added to the map's "strong here" list
  (a pro ban means teams consider it a must-answer on that map).
- Ranked win delta feeds the recommender's meta term directly; ranked ban rates are kept for ban suggestions.
